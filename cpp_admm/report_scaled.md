- 日期:2026-08-18
- 依赖:`optim_scaled/`(由仓库根 `make_optim_scaled.py` 生成,纯标准库 Python)
- 结论先行:**`--scale-rows` 是与求解算法无关的纯代数输入变换**,可前移为
  数据预处理(`optim_scaled/`),任何求解器跑它无需任何 flag 即获得均衡

## 1. 为什么均衡是"数据预处理"(与算法无关)

cpp_admm 的 `scaleRows()` 在引擎求解**之前**对 QP 做两件事
(model.cpp:323-342):

- **列均衡**:每变量除以自身交易带 band,并相应变换 P/q(返回时把 x 乘回);
- **行均衡**:每行除以自身 target 尺度(box 行=交易带、delta/gross 行=
  1e5/5e7)。

它不触碰任何求解器的内部逻辑,只是改变模型的坐标系与条件数。证据链:

1. 同一份 `scaleRows()`,osqp/qpalm/proxqp **三套不同算法**得到一致的
   提速(25×/9×/87×)与一致精度(见 §7.6)——若它依赖特定算法,不会三处
   同效。
2. OSQP 自带的 `scaled_termination`(内部均衡)**无效**(§7.6 结论 3):
   内部均衡只改条件数、不改容差语义,与手动逐行/列均衡是两回事。

因此"均衡"可以、也应该被表述为**对输入数据的预处理**,而不是求解器的
专有开关。下面的 `optim_scaled/` 把同一变换写进数据,证明这一点。

## 2. 数据预处理变换:列均衡 × 行均衡(可逐项对账)

`make_optim_scaled.py`(仓库根,mose/ 下)读 `optim_inputs/` 三个 CSV,
输出 `optim_scaled/` 同名三文件 + `scale_map.csv`(sym→band,供解后还原)。

### 2.1 为什么必须"列+行"同时做:三个尺度跨度(实测)

| 跨度 | 数据证据(optim_inputs 实测) | 不治会怎样 | 由谁治 |
|---|---|---|---|
| ① 跨品种有效交易带 | band 分布 p0=1 / p50=2.6e5 / p100=7.5e5,**314 个不同值**;注意是 trade界∩仓位界 的 xl/xu,非原始 trade 界(1605.T minTrade=−7.5e5 但 xl=−3.4e5,仓位地板绑定) | 逐品种 box/TUB/GUB 行失衡 | 列均衡 |
| ② 跨行约束目标 | 66 条 net 行尺度全部 1e5,gross_ptf=5e7,**500×**;全局停机判据 `eps_rel×max行范数` 被锚到 5e7——eps_rel=1e-3 时全局容差 5e4=吃掉 delta 行自身尺度的 50%,1e-2 时 500% | **1e-3 崩 122%、1e-2 崩 134%**(§5.1/§7.6 的悬崖) | 行均衡 |
| ③ 目标曲率 vs 界 | P 对角(lambda+tlambda)min=1.7e-9 vs 界 1e5~5e7,**KKT 元素跨度 ~3e16**(逼近双精度极限) | osqp/qpalm 误报 primal/dual infeasible(§7.6) | 列均衡(×band²) |

三个跨度**乘性叠加**,只治其一不行(只做行均衡仍误报 infeasible,只做列
均衡悬崖仍在)。

### 2.2 列均衡(逐品种):换元 x_i = b_i·x′_i

每只股票按自己的交易带换元(与 model.cpp buildProblem 同式):

```
band_i = max(1, max(|xl_i|, |xu_i|))
xl_i   = max(minTrade, minPos - pos)     # 有效卖出下限(防御:账本越界时>0=强制买入)
xu_i   = min(maxTrade, maxPos - pos)     # 有效买入上限
```

换元代入目标后,为使 loader 重算的派生量(adj、xl/xu)自动跟上,唯一一致
的字段变换:

| 字段 | 变换 | 代数依据 |
|---|---|---|
| position / minTrade / maxTrade / minPosition / maxPosition | ÷ band | 名义值(notional,日元)量纲:新箱=[xl/b, xu/b] ⊆ [−1,1];pos′+x′=(pos+x)/b |
| alpha | × band | 需 α′−λ′pos′=(α−λpos)·b;取 λ′=λb²、pos′=pos/b 后 λ′pos′=λpos·b,反解 α′=αb |
| cost | × band | c·\|x\| = c·b·\|x′\| |
| lambda / tlambda | × band² | 二次项换元产生 b²(曲率吃带宽平方;P 对角 1.7e-9~2 → 0.04~1.2e3,中位 261) |
| grp / rebate / rebateLocate | 透传 | 与求解无关 |

效果:P 对角与 A/界回到同一数量级区间(跨度 3e16 → ~5 个数量级),
KKT 条件数恢复正常。

### 2.3 行均衡(逐约束):整行 ÷ σ_k

求解器内置版(scaleRows)对**每一条行**都有自己的 σ,按行类型分六类:

| 行类型 | σ = | 本数据集实际值 | 代码 |
|---|---|---|---|
| NET / NET_TRADE | max(1, max(\|lb\|,\|ub\|)),用 CSV 原始边界(锚业务语义,不随持仓漂移) | 66 条全部 **1e5** | model.cpp:220-254 |
| GROSS | max(1, \|ub\|) | **5e7** | model.cpp:276 |
| box(逐品种交易箱) | 该品种 band | 逐品种 1~7.5e5 | model.cpp:171 |
| TUB(u±x≥0) | 2·band(x、u 两个 band 量级之和) | 逐品种 2~1.5e6 | model.cpp:175-176 |
| GUB(g±x≥pos) | max(1, \|pos\|+band) | 逐品种 ~2e4~1.2e6 | model.cpp:181-184 |
| relax 弹性 t 行 | 1(本数据未触发) | — | model.cpp:230 等 |

数据级预处理只显式做前两类(CSV 里的约束行):**σ_k = max(1,max(|lb|,|ub|))**,
`lb′=lb/σ, ub′=ub/σ`——67 条约束只产生两个值(1e5×66、5e7×1),变换后
全部落进 [−1,1]/[0,1]。box/TUB/GUB 不在数据文件里(引擎建模生成),但
pos/界已 ÷band 后它们**天然归一**(有效箱⊆[−1,1]、GUB 边界 pos/band≈O(1)),
§4 交叉验证确认了这一等价。

### 2.4 交汇点:weight 的 23,628 个条目,每个单独算

行、列均衡在权重矩阵上相乘:

```
w'(k,i) = w(k,i) · band_i ÷ σ_k
```

同一约束内不同股票系数不同(gross_ptf:1332.T→0.00265、1605.T→0.00684),
同一股票在不同约束下又不同(delta_ptf 的 1605.T→3.42)。

**代数等价校验**(关键,非近似;loader 视角):

- NET:`adj′ = Σ w′·pos′ = Σ(w·b/σ)(pos/b) = adj/σ` ✓;
  行 `Σ w′·x′ = (Σ w·x)/σ ∈ [(lb−adj)/σ, (ub−adj)/σ]` ✓,GROSS 同理。
- 目标:线性项 `(α−λpos)x → (α−λpos)·b·x′`,二次项自动配平 ×band²,
  **目标函数值在换元下不变**(这是 §3 中 scaled 目标可与参考原地比较的原因)。
- 可行集与最优解数学不变,仅坐标系不同。

运行:`python3 make_optim_scaled.py` → `optim_scaled/{optim_inputs,
optim_constraints,optim_weights}.20260520` + `scale_map.csv`
(358 品种 / 67 约束 / 23628 权重行)。

### 2.5 解后恢复(乘回 band)

```
trade_i     = x′_i · band_i                   # scale_map.csv 查表
targetPos_i = (pos′_i + x′_i)·band_i = pos_i + trade_i
```

- **目标值不用恢复**:换元保值(§2.4),直接对比。
- **对偶变量**(如需):行乘子 `y_k = y′_k/σ_k`(缩放行=原行/σ);
  逐变量对偶/梯度与 x 同方向乘回 band。
- 求解器内置 `--scale-rows` 的恢复是同一件事的向量化:`x[j] *= varScale[j]`
  (x/u 用 band、g 用 |pos|+band、t 用 1)。
- 验证闭环(§3):恢复后逐笔 vs MOSEK 原始输出 mean 3.2/max 50.8
  (≈band 的 0.001%),gross/delta 贴界。

## 3. MOSEK 实测:optim_scaled vs optim_inputs

golang MOSEK 引擎(`bin/jobd --engine=mosek`,CGO 编译自
`golang_mosek/src`,library 与 license 同 §7.2)。

| 项 | optim_inputs(原) | optim_scaled(预处理) |
|---|---|---|
| wall ×3 | 0.54 / 0.58 / 0.54 s | 0.51 / 0.54 / 0.57 s |
| MOSEK 内点迭代 | 18(求解侧 0.19s) | 23(求解侧 0.14s) |
| 目标(还原后) | 6580.227933 | 6580.247014((+0.00029%)vs ref) |
| 参考目标 | 6580.2285 | 6580.2285 |
| gross / delta | 4.99996e7 / +99999.7 | 4.99995e7 / +99999.7 |
| 逐笔 vs reference | — | mean 3.2 / max 50.8(≈band 0.001%) |

解读:

- **MOSEK 无提速也无损失**(wall 0.54s vs 0.54s):MOSEK 是内部已充分
  均衡的 IPM,数据级再均衡对它"既不坏也不快"。这正是"引擎无关"的另一面
  ——均衡不会伤害任何求解器。
- 迭代数 18→23 是 IPM 对不同 KKT 坐标系的正常路径分叉,求解侧时间反而
  0.19→0.14s 略降。
- **准确性终点**:目标、gross/delta、逐笔全部贴参考/MOSEK 基准。

## 4. cpp_admm 交叉验证:数据级缩放 ≡ 内置 --scale-rows

同一求解器两种路径:

| 引擎 | 原数据 + `--scale-rows` | scaled 数据(无 flag) | 逐笔差 |
|---|---|---|---|
| osqp | 0.21s | 0.26s | mean 0.014 / max 0.37 |
| qpalm | 0.08s | 0.085s | mean 0.0033 / max 0.13 |
| proxqp | 0.11s | 0.12s | mean 0.0007 / max 0.08 |

(逐笔差为 scaled 解 ×band 还原后 vs 内置 --scale-rows 原坐标解;时间
噪声 ~0.05s 量级。)

- 三引擎目标 6579.757 ±0.001(−0.007%),gross=5e7、delta=1e5 贴界,
  与 §7.6 均衡后行一致。
- 但注意:scaled 无 flag 的速度(0.26/0.085/0.12s)是否真的"免费"?
  见 §5 —— 它比 §7.6 均衡基准(0.17/0.045/0.078s)仍慢 ~1.5×,
  原因不是数据变换失效,而是 §7.6 的基准在同一软硬件下复测为
  0.21/0.08/0.11s(见下),与 scaled 路径同量级。

### 4.1 同机复测 vs 报告中基准(时间口径)

§7.6 报告的 0.17/0.045/0.078s 与此处实时不同(clang/gcc 版本或机器
负载),为避免误导,本报告以**同一二进制、同一时刻**串行对比为准:

| 引擎 | 原+`--scale-rows`(同机) | scaled 无 flag(同机) | 比值 |
|---|---|---|---|
| osqp | 0.21 / 0.21 / 0.21 s | 0.26 / 0.26 / 0.26 s | ~1.2× |
| qpalm | 0.08 / 0.08 / 0.08 s | 0.08 / 0.09 / 0.09 s | ~1.1× |
| proxqp | 0.11 / 0.11 / 0.10 s | 0.12 / 0.12 / 0.13 s | ~1.1× |

scaled 无 flag ≤ 1.2× 内置 flag,两者数学等价;剩余微小差异来源:
数据变换与 scaleRows 对固定变量/relax 的处理顺序(见 §7.6 注),量级
远小于无均衡时的 20~87× 差距。

的损失%;数据 `/tmp/mose_run/sweep_summary.txt`,扫列为 no/scale/st):

|---|---|---|---|
| 1e-8 | 0.007% / 0.17s | 0.007% / 0.046s | 0.007% / 0.079s |

- **最接近 10ms 的点**:osqp 均衡对角线 1e-2/1e-2 = total 14.7ms /

- 精度的"可接受阈值"是主观参数:~0.01% 对应 qpalm 均衡 ×10⁴
  (38ms,几乎白拿),1%/2% 分别对应 osqp ~1e-3(60ms)/1e-2(15ms)。

详细无均衡对照(osqp 1e-3 崩 122%、1e-2 崩 134%;qpalm 1e-2 崩 45%)见
§7.6。均衡后的 Pareto 是诚实平滑的,不再有 1% 容差崩 122% 的陷阱。

### 5.1 无均衡下放宽容差:三条路径(比例射线 / abs 专项 / 对角线)全部不可用

问题:不做均衡,直接放宽 eps_abs/eps_rel 能否换速度?
默认参数是 abs=1e-6 / rel=1e-8(比例 100:1)。三条放宽路径:
①**比例射线**(最自然:保持 100:1 同步 ×10、×100、…);
②abs 专项(rel 钉 1e-8);
③对角线 abs=rel。
(数据 `/tmp/mose_run/sweep2|sweep3/summary_table.txt`,脚本
`/tmp/mose_run/sweep_eps2.sh`、`sweep_eps3.sh`;gap% 相对 6580.2285。)

**结果 1:比例射线(abs:rel=100:1 同步放大)——平坦到悬崖,无任何可用提速点**

| qpalm | 0.42s / 0.007% | 0.40s / 0.007% | 0.40s / 0.018% | **崩 78.6%**/76ms | **崩 92.1%**/44ms | **崩 98.6%**/36ms |
| proxqp | 6.70s / 0.007% | 4.27s / 0.018% | 1.55s / **2.97%** | **崩 79.2%**/65ms | **崩 79.2%**/65ms | **崩 79.2%**/65ms |

- **三引擎在悬崖前没有任何一个"更快且可用"的点**——最快可用点仍是

**结论**:无均衡时,三条放宽路径(比例射线/abs 专项/对角线)同构:
**悬崖前平坦(不快),悬崖后崩**——容差不是速度杠杆。均衡后同一条
射线变成平滑 Pareto(17~170ms 全可用),提速全部来自均衡本身;
若接受 ~1% 损失,osqp ×10⁵=17ms、对角线 1e-2=15ms 是仅有的 <20ms 点,
离 10ms 还差一段(剩余路径:osqp rho/alpha 调参)。

### 5.2 持仓级精度:各引擎 vs MOSEK 的 targetPosition 差(逐笔)

*\*rel max=1.0 来自 8750.T:MOSEK 留 pos=48.6,开源引擎推到恰好 0
(|x| 折点上的平坦方向),绝对差只有 48.6。*

三个引擎在 rel=1e-8 处给出**几乎相同的差**(166.6/166.7/166.6)——
这不是各自求解器的噪声,而是它们与 MOSEK 在**同一批平坦方向上的系统性
分歧**。容差从 1e-8 收到 1e-6 该值纹丝不动(166.3~166.9),证明它是
问题结构的地板,不是求解精度。

**分布**(osqp rel=1e-8,单位名义值):p50=0.24、p90=10.2、p99=85、max=167;

**结论**:

1. **abs < 1e-3 跨求解器不可达**:地板 ~167(0.03% 典型 band),且与
   容差无关。原因不是求解精度,而是**最优解面平坦**(§7.5.1 机理):
   同一目标值下存在一族持仓组合,每个求解器的收敛路径停在该流形的不同
   点;MOSEK 同二进制复跑 10 次也有 0.0105 的散布(见
   report_diff_analysis.md),其中 70/358 品种 spread>1e-3——**连 MOSEK
   自身复跑都超 1e-3 线**。
2. 中位品种 p50=0.24(名义值):一半持仓跨求解器高度一致,分歧集中在 115 个
   大持仓/折点品种的平坦方向上。
3. 若业务要求 1e-3(名义值)级持仓可复现,钉死求解器与参数也**不够**(物理
   上限 ~0.01 日元),唯一出路是**加微小正则**(提高 λ/τ 或加 ℓ2 prox)消除平坦性
   使解唯一——以可控的微小目标损失换取持仓唯一性。

## 6. 结论

1. **均衡 = 数据预处理,与算法无关**:同一变换既可写进引擎内
   (`--scale-rows`),也可前移成 `optim_scaled/`,三引擎+MOSEK 逐笔等价。
2. **MOSEK 上均衡无损无增**:MOSEK 目标复现 6580.2285(gross/delta 贴界),
   wall 不因预处理改变;收益只在无内部均衡的开源 ADMM 家族。
3. **速度现实**:scaled 无 flag 与内置 `--scale-rows` 同机同量级
   (~1.1–1.2×),目标 −0.007%;无均衡下放宽容差不可换速度(§5.1 三条
   路径全部证伪),均衡后同一条比例射线变成平滑 Pareto(qpalm ×10⁴ =
   38ms/0.010% 几乎白拿;osqp ×10⁵ = 17ms/0.96%);<20ms 仅有的两点是
   osqp 均衡 1e-2/1e-2(14.7ms/1.85%)与 ×10⁵(17.3ms/0.96%),离 10ms
   的剩余路径只有 osqp rho/alpha 调参。
